# Мышцы — тренажёр

Карточки с интервальными повторениями по таблице 15.2 «Основные мышцы тела человека и их функции».

- 46 мышц, по одной карточке на мышцу. В ответе разделы: начало, прикрепление, функции, иллюстрация, «Как запомнить», упражнения
- вопрос по мышце задаётся по названию, по картинке («что это за мышца и всё о ней») или вперемешку
- 32 обратных вопроса («что начинается от седалищного бугра?», «какие мышцы отводят бедро?»)
- вход через Google или по ссылке на почту, доступ только по списку email
- прогресс синхронизируется между телефоном и компьютером

## Структура папки

| Путь | В git? | Что это |
|---|---|---|
| `index.html` | да | всё приложение (HTML + CSS + JS, без сборки) |
| `firebase-config.js` | да | конфиг Firebase; не секрет, доступ ограничивают правила |
| `firestore.rules` | да | правила доступа; копия того, что вставлено в консоль Firebase |
| `.gitignore` | да | исключает материалы и `.DS_Store` |
| `content-src/` | **нет** | исходники материалов: тексты, упражнения, картинки, скрипт сборки |
| `content.json` | **нет** | собранные материалы для загрузки в Firestore |

**Почему материалы не в git.** Репозиторий и сайт на GitHub Pages публичные, и любой файл оттуда можно скачать по прямой ссылке. Поэтому таблица и картинки из учебника лежат в Firestore, а читать их можно только после входа с email из списка доступа. В репозитории только код.

## Как это устроено

- **Вход:** Firebase Authentication. Можно войти через Google или по одноразовой ссылке на почту. Ссылка нужна, если у человека нет Google-аккаунта. На каждом устройстве входить нужно один раз, потом сессия сохраняется.
- **Материалы:** документ `content/main` (тексты) и коллекция `images/<номер>`: картинки хранятся как data URL в base64, один документ на картинку, лимит Firestore 1 МБ на документ. Firebase Storage не используется, потому что он требует платного тарифа Blaze.
- **Доступ:** правила Firestore проверяют `email` в токене. Если email нет в списке, сайт показывает «Нет доступа».
- **Прогресс:** у каждого свой документ `users/<uid>`, а также копия в localStorage. При расхождении по каждой карточке побеждает более свежий ответ.

## Первая настройка Firebase (≈15 минут, бесплатно)

1. **Проект.** https://console.firebase.google.com → Create project. Google Analytics не нужен. Тариф Spark, карта не нужна.
2. **Firestore.** Firestore Database → Create database → регион поближе (например `eur3`, потом его не поменять) → *production mode*.
3. **Правила.** Firestore → Rules → вставить `firestore.rules`. Впишите свой email в двух местах (`YOUR_EMAIL`) и email остальных в список. Все адреса маленькими буквами. Нажмите **Publish**.
4. **Вход.** Authentication → Get started → Sign-in method:
   - **Google** → Enable;
   - **Email/Password** → Enable + **Email link (passwordless sign-in)**.
5. **Домен.** Authentication → Settings → Authorized domains → добавить `<логин>.github.io`. `localhost` там уже есть.
6. **Конфиг.** Project settings → General → Your apps → `</>` (Web) → скопировать `firebaseConfig` в `firebase-config.js` вместо `null`.
7. **Материалы.** В папке проекта запустите `python3 -m http.server` → http://localhost:8000 → войдите **своим** аккаунтом → «Материалов пока нет» → выберите `content.json`.
8. **Проверка.** Firestore → Data: должны появиться `content` (1 документ), `images` (48), `users` (после первой карточки).

Если меню консоли выглядит иначе, откройте разделы напрямую:
`https://console.firebase.google.com/project/<ID>/authentication/providers` и `…/firestore`.

## Публикация на GitHub Pages

1. Создайте **публичный** репозиторий (на бесплатном тарифе Pages работает только с публичными), запушьте папку. `content.json` и `content-src/` не попадут в репозиторий благодаря `.gitignore`.
2. Settings → Pages → Source: *Deploy from a branch* → `main` / `(root)`.
3. Через минуту сайт будет доступен по адресу `https://<логин>.github.io/<репозиторий>/`.

## Доступ для других людей

1. Впишите email в список в правилах Firestore (Firestore → Rules) → Publish. Обновите и `firestore.rules` в репозитории, чтобы копия совпадала.
2. Отправьте человеку ссылку на сайт. Он входит через Google или по ссылке на почту.
   - Письмо со ссылкой может попасть в «Спам».
   - Ссылку лучше открывать на том же устройстве, где вводили email. На другом устройстве сайт попросит ввести адрес ещё раз.

## Как обновить материалы

Всё, что видно на сайте, лежит в `content-src/`:

| Файл | Что внутри |
|---|---|
| `muscles.json` | 46 мышц: `n` — номер, `g` — блок (`trunk` / `arm` / `leg`), `name`, `o` — начало, `i` — прикрепление, `f` — функции, `hint` — «Как запомнить», `ex` — список упражнений |
| `reverse.json` | обратные вопросы: `id`, `g`, `q` — вопрос, `a` — ответ |
| `rules.html` | вкладка «Правила» |
| `groups.json` | названия блоков |
| `images/` | `1.jpg` … `46.jpg` по номеру мышцы, `front.jpg` / `back.jpg` — обзорные рисунки |

Порядок:

1. Поправьте файл или замените картинку файлом с тем же именем (до ~900 КБ).
2. В корне проекта выполните `node content-src/build-content.mjs`. Скрипт проверит данные (пустые поля, повторяющиеся номера, размер картинок) и пересоберёт `content.json`.
3. Откройте сайт под владельцем → ⚙ → «Обновить материалы» → выберите `content.json`.

Остальные увидят изменения при следующем открытии сайта. Прогресс привязан к номеру мышцы, поэтому **номера `n` не меняйте**: если номер поменяется, карточки этой мышцы начнутся заново.

Мелкую опечатку можно поправить прямо в консоли (Firestore → Data → `content/main`). Но ту же правку нужно внести в `content-src`, иначе следующая загрузка её перезапишет.

## Локальная проверка без Firebase

Если в `firebase-config.js` стоит `null`, сайт берёт `content.json` из той же папки, а прогресс хранит только в браузере. Запустите `python3 -m http.server` в папке проекта и откройте http://localhost:8000. Если открыть `index.html` двойным кликом, `content.json` не загрузится.

## Как пользоваться

- **Тренировка.** Выберите блок (туловище / руки / ноги), что учить (мышцы и/или обратные вопросы) и как задавать вопрос по мышце: по названию, по картинке или вперемешку. Сначала идут карточки к повторению, потом новые: мышцы блока по порядку, а после них обратные вопросы этого блока. Лимит новых в день настраивается. Расскажите про мышцу (начало, прикрепление, функции), откройте ответ и оцените себя:
  - **Не помню** — карточка вернётся через пару карточек;
  - **Трудно / Помню / Легко** — следующий показ через 1 день, 3 дня, неделю и дальше с растущим интервалом.
- **Точно знаю** (между «Показать ответ» и «Пропустить», клавиша 4) — засчитать карточку как «Легко», не открывая ответ.
- **Пропустить** (кнопка рядом с «Показать ответ», клавиша → или S) — перейти дальше, не открывая ответ и без оценки, расписание не меняется. Пропущенная карточка вернётся в конце тренировки, а пропущенная второй раз останется до следующей.
- **Прогнать всё.** Все выбранные карточки вперемешку, расписание не меняется. Для повторения накануне экзамена.
- **Правила.** Обзорные рисунки и закономерности с мнемониками.
- **Таблица.** Полный текст с картинками, подсказками и упражнениями. Есть поиск: «седалищный», «отводит бедро», «румынская».
- **⚙.** Аккаунт, резервная копия прогресса в файл, сброс, обновление материалов (только владелец).
- Клавиши: пробел — показать ответ, 4 — точно знаю, → или S — пропустить, 1–4 — оценка. Картинки увеличиваются по нажатию.

> Упражнения (`ex`) — не из учебника. Они составлены по общепринятой кинезиологии и сверены с функциями из таблицы.
